# User Story Mapping и критерии приёмки — АС «Учёт инструментов» v2

Шаги 3–4 ДЗ3. База интерфейса — концепция 3 «Корпоративный» ([ui_description.md](ui_concepts/ui_description.md)). Список функций F1–F7 — в [project_description.md](project_description.md). Подробная обработка ошибок и коды — в разделе 7 [technical_specification.md](technical_specification.md).

**Как читать.** «**есть**» — функция уже работает в текущей системе (`App`), для неё критерии записаны по фактическому поведению; «**v2**» — новое требование. Тексты сообщений **API** в критериях совпадают с сообщениями текущего сервера (сверено с кодом). Элементы и тексты **интерфейса**, которых нет в текущем клиенте, помечены **«UI v2»**: это требования к новому интерфейсу, а не описание существующего.

## 1.1. Что в критериях относится к UI v2

В текущем клиенте нет (проверено по `public/js`): текста «Ничего не найдено» и кнопки «Сбросить фильтры» (сейчас «Инструменты не найдены»); баннера сетевой ошибки с кнопкой «Повторить» (сейчас общее уведомление); подписи ошибки под конкретным полем (сейчас одно общее поле в форме); текста «Данных пока нет»; кнопки «Экспорт CSV» (есть только API); числа дней просрочки в строке (есть метка «просрочено»). Соответствующие критерии — US-01 №3–4, US-02 №2–3 (расположение сообщения), US-05 №1 (число дней), US-07 №2, US-11 №1 и №3 (кнопка), US-15 №3 — это **UI v2**.

## 2. Пользовательские пути

### Путь 1. «Счастливый путь»: выдача инструмента (Кладовщик)

| Шаг | Действие пользователя | Реакция системы |
|---|---|---|
| 1 | Входит в систему | Открывается список инструментов (US-06, US-01) |
| 2 | Вводит «makita» в поиск | В таблице остаётся ИНВ-0002 «Шуруповёрт Makita» (US-01) |
| 3 | Выбирает строку, нажимает «Выдать» | Открывается форма: сотрудник, срок возврата |
| 4 | Выбирает сотрудника, указывает срок, подтверждает | Статус меняется на «Выдан», в панели появляется запись в истории (US-03) |

### Путь 2. Нормальный сценарий: возврат с поломкой (Кладовщик)

Выбирает выданный инструмент → «Принять возврат» → в поле «Состояние» пишет «Треснула рукоятка», отмечает «Отправить в ремонт» → статус «В ремонте», примечание сохранено (US-04).

### Путь 3. Нормальный сценарий: контроль (Руководитель)

Входит → «Отчёты» → видит счётчик «Просрочено: 1» → открывает список просрочек → выгружает CSV для рассылки начальникам участков (US-05, US-07, US-11).

### Путь 4. Негативный сценарий: попытка двойной выдачи

Кладовщик нажимает «Выдать» у инструмента, который в это время уже выдан с другого рабочего места → система отвечает «Инструмент нельзя выдать: он уже выдан»; форма остаётся открытой, список обновляется, а кнопка «Выдать» у этой строки блокируется (US-03).

## 5. Истории и критерии приёмки

Формат критериев: **Given** (дано) · **When** (когда) · **Then** (тогда). Метки: ✅ позитивный, ⛔ негативный.

---

### US-01 · Найти инструмент · Must · есть
**Как** кладовщик, **я хочу** искать инструменты по названию, номеру или производителю и фильтровать их по категории и статусу, **чтобы** быстро найти нужный.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | В базе есть инструменты Bosch | Ввожу «bosch» или «дрель» в поиск (в любом регистре) | В списке только инструменты, у которых в названии, инв. номере или производителе есть введённая подстрока. **Замечание:** текущий поиск (`LIKE` в SQLite) регистронезависим только для латиницы — «дрель» не найдёт «Дрель»; для кириллицы это требование v2 (ТЗ, ФТ-1.4) |
| 2 | ✅ | В базе есть инструменты в разных статусах | Выбираю фильтр статуса «Выдан» | В списке только инструменты со статусом «Выдан» |
| 3 | ⛔ | Ни один инструмент не подходит под запрос | Ввожу «zzz» | Вместо таблицы текст «Ничего не найдено» и кнопка «Сбросить фильтры» |
| 4 | ⛔ | Сервер недоступен | Открываю список | Сообщение «Не удалось загрузить данные. Проверьте соединение» и кнопка «Повторить»; предыдущий список не стирается |

### US-02 · Добавить инструмент · Must · есть
**Как** кладовщик, **я хочу** добавить новый инструмент с инвентарным номером, **чтобы** он появился в учёте и его можно было выдать.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Заполнены инв. номер, наименование, категория | Нажимаю «Сохранить» | Инструмент создан со статусом «На складе», появился в списке, форма закрылась (ответ 201) |
| 2 | ⛔ | Инструмент с номером «ИНВ-0001» уже есть | Сохраняю новый инструмент с тем же номером | Ответ 409, в форме текст «Инструмент с таким инвентарным номером уже есть»; введённые данные сохранены |
| 3 | ⛔ | Поле «Наименование» пусто | Нажимаю «Сохранить» | Ответ 400, под полем «Поле «Наименование» обязательно для заполнения»; фокус на поле |
| 4 | ⛔ | В поле «Цена» введено «-5» | Нажимаю «Сохранить» | Ответ 400, «Цена должна быть неотрицательным числом» |

### US-03 · Выдать инструмент · Must · есть
**Как** кладовщик, **я хочу** выдать инструмент сотруднику с указанием срока возврата, **чтобы** всегда знать, у кого он находится.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Инструмент «На складе», выбран сотрудник, срок не раньше даты выдачи | Подтверждаю выдачу | Создана запись выдачи (201), статус инструмента «Выдан», в панели деталей в истории появилась запись |
| 2 | ⛔ | Инструмент уже выдан | Пытаюсь выдать | Ответ 409, «Инструмент нельзя выдать: он уже выдан»; форма остаётся открытой |
| 3 | ⛔ | Инструмент в ремонте | Пытаюсь выдать | Ответ 409, «Инструмент нельзя выдать: он находится в ремонте»; кнопка «Выдать» у такого инструмента недоступна (disabled) |
| 4 | ⛔ | Срок возврата раньше даты выдачи | Подтверждаю | Ответ 400, «Срок возврата не может быть раньше даты выдачи» |
| 5 | ⛔ | Срок возврата не указан | Подтверждаю | Ответ 400, «Поле «Срок возврата» обязательно для заполнения» |
| 6 | ⛔ | Выбранный сотрудник удалён другим пользователем | Подтверждаю | Ответ 404, «Сотрудник не найден», список сотрудников в форме обновляется |

### US-04 · Принять возврат · Must · есть
**Как** кладовщик, **я хочу** принять инструмент обратно, зафиксировав его состояние, **чтобы** вернуть его в оборот или отправить в ремонт.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Есть открытая выдача | Принимаю возврат без отметки о ремонте | Выдача закрыта (дата возврата — сегодня), статус инструмента «На складе» |
| 2 | ✅ | Есть открытая выдача | Указываю «Треснула рукоятка» и отмечаю «В ремонт» | Статус «В ремонте», примечание инструмента = «Треснула рукоятка» |
| 3 | ⛔ | Выдача уже закрыта (другим кладовщиком) | Принимаю возврат ещё раз | Ответ 409, «Инструмент уже возвращён»; статус не меняется |
| 4 | ⛔ | Дата возврата раньше даты выдачи | Подтверждаю | Ответ 400, «Дата возврата не может быть раньше даты выдачи» |
| 5 | ⛔ | Состояние длиннее 300 символов | Подтверждаю | Ответ 400, «Поле «Состояние при возврате» длиннее 300 символов» |

### US-05 · Видеть просрочки · Must · есть
**Как** кладовщик или руководитель, **я хочу** видеть инструменты, не возвращённые к сроку, **чтобы** напомнить сотрудникам.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Есть выдача без возврата, срок которой прошёл | Открываю список выдач (кладовщик и руководитель) или отчёт (только руководитель) | Строка выделена; **UI v2:** указано число дней просрочки; в отчёте счётчик «Просрочено» ≥ 1 |
| 2 | ✅ | Срок возврата сегодня | Открываю список | Выдача не считается просроченной (просрочка — только после даты срока) |
| 3 | ⛔ | Просрочек нет | Открываю блок просрочек | Текст «Просроченных возвратов нет» |

### US-06 · Вход и роли · Must · **v2**
**Как** пользователь, **я хочу** войти по логину и паролю и получить доступ только к своим функциям, **чтобы** действия в системе были персональными, а данные защищены.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Есть пользователь с ролью «Кладовщик» | Ввожу верные логин и пароль | Открывается список инструментов; в шапке показаны роль и кнопка «Выйти» |
| 2 | ⛔ | — | Ввожу неверный пароль | Ответ 401, «Неверный логин или пароль» (без уточнения, что именно неверно); пароль не очищает логин |
| 3 | ⛔ | 5 неудачных входов подряд с одним логином | Пробую войти в шестой раз | Ответ 429, «Слишком много попыток. Повторите через 15 минут» |
| 4 | ⛔ | Не выполнен вход | Открываю адрес списка или обращаюсь к `/api/tools` | Для страницы — переход на вход; для API — ответ 401; данные не возвращаются |
| 5 | ⛔ | Вошёл кладовщик | Открываю раздел «Отчёты» или пытаюсь списать инструмент | Ответ 403, «Недостаточно прав»; пункт «Отчёты» в меню не показывается |
| 6 | ⛔ | Сессия неактивна 8 часов | Выполняю любое действие | Ответ 401, показывается экран входа с текстом «Сессия истекла. Войдите снова»; несохранённая форма не теряется молча (см. ТЗ, ERR-AUTH-03) |

### US-07 · Сводный отчёт · Should · есть
**Как** руководитель, **я хочу** видеть сводку по парку, **чтобы** принимать решения о закупке и списании.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | В базе есть инструменты и выдачи | Открываю «Отчёты» | Показаны: всего инструментов (без списанных), стоимость парка, количества по статусам, число просрочек, разбивка по категориям, топ-5 сотрудников с невозвращёнными инструментами |
| 2 | ⛔ | В базе нет инструментов | Открываю «Отчёты» | Нулевые показатели и текст «Данных пока нет»; страница не падает |
| 3 | ⛔ | Роль «Кладовщик» | Открываю «Отчёты» | Ответ 403, «Недостаточно прав» |

### US-08 · Изменить инструмент · Should · есть
**Как** кладовщик, **я хочу** исправить данные инструмента, **чтобы** справочник оставался точным.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Инструмент существует | Меняю наименование и сохраняю | Данные обновлены, изменение видно в списке |
| 2 | ⛔ | Пытаюсь вручную поставить статус «Выдан» | Сохраняю | Ответ 409, «Статус «Выдан» меняется только через выдачу и возврат инструмента» |
| 3 | ⛔ | Инструмент удалён другим пользователем | Сохраняю | Ответ 404, «Инструмент не найден», список обновляется |

### US-09 · Списать инструмент · Should · есть (права — v2)
**Как** руководитель, **я хочу** списать негодный инструмент, **чтобы** он не учитывался в парке и отчётах.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Инструмент «На складе» или «В ремонте» | Меняю статус на «Списан» | Статус «Списан»; инструмент исключён из отчёта и стоимости парка; его выдача невозможна |
| 2 | ⛔ | Инструмент выдан | Пытаюсь списать | Ответ 409, «Статус «Выдан» меняется только через выдачу и возврат инструмента»; предлагается сначала принять возврат |
| 3 | ⛔ | Инструмент с историей выдач | Пытаюсь удалить, а не списать | Ответ 409, «Нельзя удалить инструмент с историей выдач; спишите его (статус «Списан»)» |

### US-10 · Сотрудники · Should · есть
**Как** кладовщик, **я хочу** вести список сотрудников, **чтобы** выбирать их при выдаче.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | — | Добавляю сотрудника с ФИО | Сотрудник создан и доступен в форме выдачи |
| 2 | ⛔ | ФИО пустое | Сохраняю | Ответ 400, «Поле «ФИО» обязательно для заполнения» |
| 3 | ⛔ | За сотрудником числятся выдачи (в том числе закрытые) | Удаляю | Ответ 409, «Нельзя удалить сотрудника, за которым числятся выдачи (в том числе закрытые)» |

### US-11 · CSV просрочек · Should · есть
**Как** руководитель, **я хочу** выгрузить просрочки в CSV, **чтобы** открыть их в Excel и разослать.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Есть просрочки | Нажимаю «Экспорт CSV» | Скачивается `overdue.csv` с BOM, разделитель «;», колонки: инв. номер, инструмент, сотрудник, подразделение, выдан, срок возврата, дней просрочки |
| 2 | ✅ | В названии инструмента есть символы `=`, `+`, `-`, `@` в начале | Выгружаю | Значение экранировано апострофом, формула в Excel не выполняется |
| 3 | ⛔ | Просрочек нет | Нажимаю «Экспорт CSV» | Файл содержит только заголовок; в интерфейсе — «Просроченных возвратов нет» |

### US-12 · Категории · Should · есть
**Как** кладовщик, **я хочу** управлять категориями, **чтобы** группировать инструменты.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | — | Добавляю категорию «Пневмоинструмент» | Категория создана |
| 2 | ⛔ | Категория с таким названием уже есть | Добавляю | Ответ 409, «Категория с таким названием уже существует» |
| 3 | ⛔ | В категории есть инструменты | Удаляю | Ответ 409, «Нельзя удалить категорию, в которой есть инструменты» |

### US-13 · Продлить срок возврата · Nice · **v2**
**Как** кладовщик, **я хочу** продлить срок возврата выданного инструмента, **чтобы** не оформлять возврат и новую выдачу.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Есть открытая выдача со сроком 01.02.2099 | Указываю новый срок 01.03.2099 | Срок обновлён (ответ 200), в панели деталей виден новый срок |
| 1а | ✅ | Таблица `issue_events` согласована (ТЗ, ФТ-7.4) | Продлеваю срок | В истории выдачи есть запись о продлении: кто, когда, старый и новый срок (критерий действует только после согласования схемы) |
| 2 | ⛔ | Новый срок не позже текущего | Подтверждаю | Ответ 400, «Новый срок возврата должен быть позже текущего» |
| 3 | ⛔ | Инструмент уже возвращён | Подтверждаю | Ответ 409, «Инструмент уже возвращён, срок продлить нельзя» |
| 4 | ⛔ | Выдача не найдена | Подтверждаю | Ответ 404, «Запись о выдаче не найдена» |

Примечание: поведение метода API проверено прототипом в ДЗ2 (`ДЗ2/artifacts/ab_with_rules.patch`, тексты сообщений взяты оттуда; при пустом сроке — «Поле «Новый срок возврата» обязательно для заполнения», 400). Запись в истории (критерий 1а) требует изменения схемы и в прототипе не реализована.

### US-14 · Отчёт об использовании · Nice · **v2**
**Как** руководитель, **я хочу** видеть, сколько раз и как долго использовался каждый инструмент, **чтобы** решать, что докупать и что списывать.

| № | Тип | Given | When | Then |
|---|---|---|---|---|
| 1 | ✅ | Есть выдачи | Открываю «Использование инструментов» | Для каждого не списанного инструмента: число выдач, дней «на руках», дата последней выдачи; сортировка по дням по убыванию |

## 6. Покрытие

- Историй: **15** (требуется минимум 5); приоритеты — Must 6, Should 6, Nice 3.
- Все истории в формате «Как [роль], я хочу [действие], чтобы [результат]».
- Критерии Given-When-Then — **для каждой** истории; у каждой есть позитивный и негативный сценарии.
- Каждая функция F1–F7 покрыта минимум одной историей (F1: US-01, 02, 08, 09; F2: US-03, 04; F3: US-05, 11; F4: US-07, 14; F5: US-10, 12; F6: US-06; F7: US-13).
- Типы негативных сценариев: ошибки валидации, отсутствие данных, сетевые ошибки, неавторизованный доступ, конфликты состояния.
