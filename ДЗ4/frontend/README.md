# АС «Учёт инструментов» — frontend (ДЗ4)

Одностраничное приложение на React для существующего бэкенда «Учёт инструментов» (папка `App` из ДЗ1–ДЗ2). Интерфейс построен по концепции 3 «Корпоративный» из ДЗ3: боковое меню, таблица и карточка выбранного инструмента.

## Возможности

| Экран | Что делает |
|---|---|
| **Инструменты** | Поиск и фильтры (категория, статус), таблица, карточка с историей выдач, добавление инструмента, выдача и приём возврата |
| **Выдача и возврат** | Список выдач с фильтрами «Активные / Просроченные / Все», приём возврата, число дней просрочки |
| **Отчёт** | Плитки-показатели, круговая диаграмма «Структура парка по статусам», разбивка по категориям, топ сотрудников, просрочки, экспорт CSV |
| **Вход** | Выбор одной из трёх ролей (см. ниже); без входа остальные адреса недоступны |

На каждом экране обработаны состояния загрузки, ошибки (сетевой и серверной, с кнопкой «Повторить»), пустого списка и успеха. Интерфейс адаптивен: на ширине менее 1280 px карточка уходит под таблицу, менее 1024 px — меню становится горизонтальной лентой.

Чего нет (в бэкенде этого нет): пароли и серверная проверка прав, продление срока, отчёт об использовании, управление сотрудниками и категориями. Они описаны в ТЗ ДЗ3 как v2.

## Роли и доступ

Вход выполняется выбором роли на странице `/login`. Выбранная роль хранится в `sessionStorage` и сбрасывается при закрытии вкладки или нажатии «Выйти». Адрес, открытый до входа, запоминается: после входа пользователь попадает на него, если роль это позволяет.

| Роль | Разделы | Изменение данных |
|---|---|---|
| Кладовщик | Инструменты, Выдача и возврат, Отчёт | Добавление инструментов, выдача, приём возврата |
| Руководитель | Инструменты, Выдача и возврат, Отчёт | Нет (кнопки записи скрыты) |
| Сотрудник | Только Инструменты; история выдач в карточке скрыта и не запрашивается | Нет |

Раздел, закрытый для роли, не показывается в меню, а прямой переход по адресу открывает сообщение «Доступ запрещён» без запроса данных. Права описаны в одном месте — `src/auth/roles.js`.

**Это защита только интерфейса, не данных.** Бэкенд не проверяет, кто обращается к `/api/*`, и принимает любые запросы. Пока в нём нет аутентификации, роли предотвращают случайные действия, но не злонамеренные. Настоящая проверка прав должна появиться на сервере (сессии или токены), а таблица прав из `roles.js` послужит для неё образцом.

## Стек

React 19 · React Router 7 · Vite 8 · Tailwind CSS 4 · Vitest 5 + Testing Library.

## Запуск

Нужен Node.js 22.5 или новее. Два терминала.

**1. Бэкенд** (из корня проекта `ДЗ`; временная БД, чтобы не менять `App/data/tools.db`):

```bash
cd App
DB_PATH=/tmp/tools-demo.db node server.js
```

Бэкенд слушает `http://localhost:3000`. В Windows PowerShell: `$env:DB_PATH="$env:TEMP\tools-demo.db"; node server.js`.

**2. Frontend:**

```bash
cd ДЗ4/frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Запросы `/api/*` проксируются на бэкенд (адрес меняется переменной `API_TARGET`).

## Тесты и сборка

```bash
npm test          # 45 тестов в 9 файлах, бэкенд не нужен (fetch подменяется)
npm run build     # продакшен-сборка в dist/
```

## Структура

```
src/
  api/          client.js (fetch, ApiError/NetworkError, таймаут), index.js (методы API)
  auth/         roles.js (роли и права), AuthContext.jsx (текущая роль), guards.jsx (защита маршрутов)
  hooks/        useAsync (загрузка/ошибка/данные), useDebounced, useSubmit
  components/   ui.jsx (базовые элементы), forms.jsx (формы), Layout.jsx, PieChart.jsx (круговая диаграмма на SVG)
  pages/        LoginPage, ToolsPage, IssuesPage, ReportPage
  utils/        format.js (даты, деньги), chart.js (геометрия секторов диаграммы)
  test/         setup.js, mockFetch.js
CLAUDE.md       правила для ИИ-агента (адаптация ДЗ2)
```

Процесс разработки и работа с ИИ-агентом описаны в [../development_report.md](../development_report.md).
